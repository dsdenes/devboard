# Design research — Watchdog page redesign (2026-10-28)

- **Task:** Redesign the selected element `#workspace-issues > section.watchdog-page` (issue #308)
  at 2101×1017. The page read as three stacked raw-data blocks: a four-cell fact grid, an
  unlabelled five-track history list, and a small table 2600px below the fold.
- **MCP status:** no MCP manager is configured in this session (`read mcp://` reports "No MCP
  manager available"), so `designmd_search_design_kits` and `designmd_get_design_kit` could not
  run. No design-kit value was invented or imported. This receipt records the limitation instead
  of claiming research that did not happen.
- **Sources of truth used instead:** `DESIGN.md` (layout, typography, components, do/don't
  rules), `design/tokens.json`, `openui.json`, the shipped `.devboard/client/app.css` primitives
  (`.panel`, `.panel__header`, `.panel__body`, `.badge`, `.table-wrap`, `.empty`), the sibling
  Issues pages (`ScoutWorkspace`, `ScoutIssues`, `IssuesWorkspace`), the shared `PageHeader`,
  `scripts/verify-watchdog.ts`, and the rendered page at 2101×1017 and 1440×900 in the running
  dashboard.
- **Observed problems:**
  1. `.watchdog-page` used `padding: 10px` and `gap: 10px` while the other Issues pages use 16px
     and 12px.
  2. The page content grew to 3511px inside `.mode-workspace` (`overflow: hidden`): the page
     section had no bounded height, so its `overflow: auto` never engaged, and the filed-issue
     table could not be reached by scrolling.
  3. The newest cycle used four equal columns (`Started`, `Action`, `Findings`, `Pending`) plus a
     separate reason line, so the verdict was split into five pieces; the age sat in 10px type at
     the far right.
  4. Cycle history had no column headers, its five tracks started at 150px/200px/90px/60px/2fr,
     and its 10–11px type made timestamps and reasons the same weight as actions.
  5. Filed issues repeated the old 10–11px table with an underlined title link, unlike the Auto
     Scout table that shipped the quiet link and 12px rows.
- **Direction adopted from the existing system:** one framed page header, one summary band whose
  first line is the action badge plus the reason and whose second line is an overline facts row;
  two labelled tables in a two-column grid on wide viewports, each panel owning its scroll; the
  Auto Scout empty composition; the existing badge tones (filed `success`, commented `accent`,
  failed `error`, none/duplicate neutral). All values map to the approved spacing scale and
  existing custom properties.
- **Rejected:** a timeline of 100 two-line cards (too tall for an audit list), a hero metric row
  (invents emphasis the data does not support), a new token or shared table component (one
  consumer, and the Auto Scout page already duplicates the table CSS locally), removing the newest
  cycle from history (the contract requires the complete retained list), and a filter/search
  control (not part of the page's journeys).
- **Effect on DESIGN.md / tokens / components:** no token, DTCG, OpenUI, or Storybook change. The
  summary band and the two tables are documented as one DESIGN.md component bullet.
